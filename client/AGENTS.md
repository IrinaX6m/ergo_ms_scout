# Scout — FRONTEND

Область: `client/**`. Соблюдать [общие инструкции](../AGENTS.md) и [задание FRONTEND](../docs/teams/FRONTEND.md).

- Работать только с UX, дизайном и клиентом, его строками, стилями и проверками. Сначала UX-002 из `../docs/UX.md`, затем схемы, проверка прототипа и визуальные макеты в `../docs/DESIGN.md`; задачи — в общем `../BACKLOG.md`.
- Не менять API, модели, миграции, Python-зависимости, CLI, очереди или развёртывание внутри фронтенд-задачи. Корневой `../locales/` относится к справке CLI.
- Контракт — `../docs/API_CONTRACT.md`; при недостатке данных описать запрос к SYSTEM и зависимость задачи, не придумывать рабочий серверный API.
- Использовать `apiClient`, компоненты, тему и механизмы интерфейса ERGOMS. Изменения общего `core/client` выделять в отдельную задачу соответствующего репозитория.
- Состояния и права определяет сервер. Проверка ввода на клиенте их не заменяет. После существенного изменения плана нужен соответствующий предпросмотр и подтверждение.
- LLM только предлагает схему, правила и план. Визуальный выбор использует сохранённый снимок; чужое содержимое изолируется от приложения.
- Для макетов и разработки допустимы обозначенные тестовые данные по согласованному контракту. Не выдавать их за готовый сбор или работающий серверный режим.
- Проверять затронутые состояния клиента; миграции, контейнеры и установку серверных зависимостей для этой задачи не запускать.
