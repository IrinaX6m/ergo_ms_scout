## Кто делает первым и что дальше

Начать с **UX-004** на действующем экране: прототип связанного выбора «снимок ↔ дерево ↔ инспектор», исправление слишком широкого выбора, клавиатура и узкий экран. Результат пользовательской проверки ещё нужно получить. SYSTEM подготовил [контракт API-004 v1](../API_CONTRACT.md#api-004--планируемые-данные-dom-дерева), его нужно сверить со сценарием. Уже описаны ветви, узел/предки, окно соседей и поиск. Передать замечания по данным до реализации, не ждать финального визуального оформления.

Затем **DES-006** оформляет согласованное взаимодействие в темах ERGOMS. После согласования данных — **FE-005**, развивая существующие компоненты. До реализации API-004 использовать обозначенные тестовые ответы из контракта: API-002 `ready`/HTML и его будущий `tree_version` → корни → ветви при раскрытии → узел/предки при клике в снимке → поиск по всем узлам → проверка правила API-002 с версией. Эти ответы не закрывают интеграцию. Дерево не собирается одним запросом, а поиск не ограничивается уже загруженными ветвями; новые маршруты пока не работают. **FE-004** проверяет новый полный сценарий с настоящим API. UX-003 для ручного режима и базовый UX-001 заново не переоткрывать.

Прочие подключения идут по FE-001–FE-003: сервер ИИ, профили прокси и серверная пагинация уже готовы. Приоритет между этими подключениями и новым инспектором определять явно; наличие нового дизайна не означает завершения остальных клиентских задач.

## Границы

Код — `client/**`, включая переводы; документы — UX.md, DESIGN.md и согласованные макеты. Применять тему и компоненты ERGOMS. Изменение общего ядра оформлять задачей его репозитория. Не менять `api/**`, миграции, Python-зависимости, CLI, его корневой `locales/**` и развёртывание. [Правила клиента](../../client/AGENTS.md).

Дерево исходных узлов нельзя восстановить из одного безопасного iframe: классы удалены, часть тегов заменена. Не ослаблять изоляцию и не загружать исходный сайт напрямую ради DOM. Новые данные передавать SYSTEM в API-004; рабочие селекторы по-прежнему проверяет API-002.

При передаче указать задачу, состояния, изменённый контракт, проверку и ограничения. Подробные критерии хранить в общем backlog, не создавать второй список задач в этом файле.
