# SCOUT — термины

Эти определения помогают обсуждать структуру. Перечень существующих классов и полей проверяется по коду; термин сам по себе не требует отдельной таблицы, службы или контейнера.

- **Задание (`Job`)** — сохранённое описание того, что нужно собрать. Его можно запускать повторно.
- **Версия плана (`JobRevision`)** — закреплённые адреса, правила и ограничения, которые пользователь проверяет и подтверждает. Изменение настройки не должно незаметно менять текущий запуск.
- **Запуск (`Run`)** — конкретное выполнение задания с выбранной версией плана, состоянием и результатами.
- **Задача (`Task`)** — ограниченная операция внутри запуска: загрузить одну страницу, найти ссылки в снимке или извлечь записи из него. Задача не равна всему сбору.
- **Попытка (`Attempt`)** — одно выполнение задачи. Повтор после ошибки является новой попыткой, а не новым заданием.
- **Координатор** — логика плана и состояния запуска. В текущем Scout она находится в коде Django; отдельный сервер для неё не обязателен.
- **Диспетчер** — выбирает готовые задачи и публикует их исполнителям, учитывая повторы и аренды.
- **Очередь и брокер** — очередь содержит сообщения о работе, брокер передаёт их исполнителям. Пустая очередь не доказывает завершение сбора: ещё работающая задача может найти новые URL.
- **Исполнитель (`worker`)** — процесс, который получает и выполняет задачи. Несколько worker'ов могут работать на одном компьютере.
- **Дополнительная машина** — другой компьютер или сервер с запущенным исполнителем. Он добавляет вычислительные ресурсы; подключение таких машин — будущий режим Scout.
- **Прокси** — посредник для обращения к сайту. Пример пути: компьютер со Scout → прокси → сайт. Прокси не разбирает HTML и не является worker'ом.
- **Снимок (`PageSnapshot`)** — сохранённый исходный HTML и сведения о загрузке. Он позволяет повторить извлечение без повторного обращения к сайту.
- **Артефакт** — сохранённый материал этапа: например, снимок или файл выгрузки. Для будущих удалённых исполнителей важен доступ к нему независимо от локального пути машины.
- **Обход (`crawl`)** — поиск ссылок и управление списком адресов. Загрузка страниц выполняется отдельными задачами.
- **Правило извлечения** — способ получить поле из конкретной структуры страницы, например CSS или XPath.
- **Схема результата** — описание полей, их типов и допустимых значений. Её будущие возможности уточняются в SPEC-001.
- **Запись (`Record`)** — полученные значения для одной единицы результата. Что считать такой единицей, ещё уточняется в Q-002.
- **Происхождение (`Evidence`)** — связь значения с источником, снимком и правилом; помогает проверить результат.
- **Аренда задачи** — время, на которое попытке разрешено выполнять работу. Истечение аренды позволяет выдать задачу повторно.
- **Номер действующей попытки (`fencing_token`)** — признак, по которому запоздалый исполнитель не может записать результат поверх более новой попытки.
- **LLM при настройке** — модель предлагает схему, правила и план на примере. После подтверждения сбор выполняется обычными обработчиками.

Различать логическую роль, процесс и физическую машину. Один компьютер может содержать несколько процессов, а несколько компьютеров в будущем могут выполнять задачи одного запуска.
