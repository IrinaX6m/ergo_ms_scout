# Scout — SYSTEM

Область: `api/**`. Соблюдать [общие инструкции](../AGENTS.md) и [задание SYSTEM](../docs/teams/SYSTEM.md).

- Серверная команда отвечает также за CLI, справку CLI, зависимости и проверки вне `api/`, как указано в `../docs/TEAM_WORKFLOW.md`.
- Не менять `../client/**` или визуальные макеты ради серверной задачи. Необходимые клиентские изменения описывать через контракт и связанные задачи FRONTEND.
- Текущий и целевой API разделять в `../docs/API_CONTRACT.md`; новые поля, состояния и ошибки согласовывать с потребителем до интеграции.
- Сохранять подтверждение версии плана, права владельца, один сбор, состояние в БД и защиту от повторной записи. Не считать пустой брокер признаком завершения.
- Основной сбор извлекает значения без LLM. Секреты прокси и провайдера не возвращать в общих ответах, плане или журнале.
- Не импортировать чужие модели: интеграции проходят через мост. Внешние идентификаторы — `public_id` и `user_public_id`.
- Дополнительные машины остаются будущим механизмом. Не поднимать Docker-пример или новую инфраструктуру как часть обсуждения структуры.
- При порученной реализации проверять конкретную серверную возможность, обновлять контракт и факт её состояния; команды тестирования — в общих инструкциях модуля.
